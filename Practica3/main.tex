\subsection{instalacion y comprobacion de nmap}

Para el caso de nmap, como en las anteriores practicas, ya se ha realizado esto 
por loq eu ya no fue necesario la instalacion de la misma, no obstante, el comando para la instalacion en todo caso 
fue este:

\begin{lstlisting}[style=consolaSeguridad]
  sudo apt-get install nmap
\end{lstlisting}

Por lo que, para comprobar que nmap este correctamente instalado 
se ejecuto el comando con la bandera -h, que es el siguiente:
\begin{lstlisting}[style=consolaSeguridad]
  nmap -h
\end{lstlisting}

y las bandeeras que se pueden utilizar, por lo que 
directamente nos indica que nmap esta instalacion, por que la consola fue lo que nos regreso.

\subsection{Utilizar nmap para iniciar las tareas de reconocimiento: }

\textbf{Utilice la herramienta nmap instalada en el equipo evilbox para iniciar con las tareas
de reconocimiento. Ejecute un escaneo rápido enviando un ping a todos los host del
segmento de red al que pertenece la dirección IP del equipo evilbox. Ejecute el
siguiente comando, ajustando el segmento de red según corresponda:}

Para esto se utilizo el el siguiente comando:

\begin{lstlisting}[style=consolaSeguridad]
  sudo nmap -sP 192.168.177.0/24
\end{lstlisting}

Donde la bandera -sP, lo que hace es que nos 
muestre todos los host activos en nuestro segmento correspondiente 
donde es por eso que se quita el utimo octeto y se remplzada por un 0 
y se le agrega la barra y el numero 24, que es la mascara de subred, por lo que
el resultado que nos arroja es el siguiente:

\begin{figure}[H]
  \centering
  \includegraphics[width=1.0\textwidth]{img/image5.png}
  \caption{Resultado del escaneo de nmap}
\end{figure}

Donde en este caso el comando nos arroja que existen 5 host activos,
donde se nos da las ip de cada uno de ellos, donde una de ellas somos nosotros, las
otras son \texttt{192.168.177.2}, \texttt{192.168.177.129}, 
\texttt{192.168.177.254} y \texttt{192.168.177.128}

\subsection{Escaneo rapido sobre los host identificado:}

Para poder ver cual es la ip que nos interesa, es necesario hacer un escaneo primero
sobre cada uno de los host, esto quiere decir cada direccion IP
que nos arrojo el comando anterior, para eso se va utilizar la bandera -F,
donde esta bandera lo que hace es que nos hace un escaneo 
rapido sobre los hosts, y la salidas que veremos sera los 
puertos que estan abiertos y los servicios que estan corriendo en cada uno de ellos, por lo que se realizo el siguiente comando:

\begin{lstlisting}[style=consolaSeguridad]
  sudo nmap -F 192.168.177.2 192.168.177.129 192.168.177.254 192.168.177.128
\end{lstlisting}

Con esta salida, s enos deja ver que la ip que nos interesa 
es la 192.168.177.129, esto por que es la unica que tiene puerto 80 con http, ademas de eso 
lo que nos da es que tiene 2 puertos abiertos y lo qeu esta corriendo en el puerto 111 es rpcbind, 
pero como se nos puso en las intrucciones el objetivo es del puerto 80.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.8\textwidth]{img/image6.png}
  \caption{Resultado del escaneo rápido sobre los host identificados}
\end{figure}

\subsection{Analisis a profundidad del puerto 80 sobre la IP destino:}

\textbf{Realice un análisis a mayor profundidad sobre el host que presenta el servicio HTTP
en el puerto 80. Utilice la bandera “-sV” para obtener la versión del software
publicado en el puerto específico. Utilice la bandera “-p” para indicar el puerto de
interés.}

Para esto lo que hace el comando con la bandera -sV es que nos da la version del software que esta corriendo en el puerto 80, y con la bandera -p le indicamos el puerto de interes, por lo que se realizo el siguiente comando:


\begin{lstlisting}[style=consolaSeguridad]
  sudo nmap -sV -p 80 192.168.177.129
\end{lstlisting}

Ahora bien, el por que del puerto 80 
es por que nos interesa, ya que es el que tiene 
el servicio http, y lo que nos arroja el comando es 
la version del software que esta corriendo en ese puerto, 
por lo que nos arroja la siguiente salida:

\begin{figure}[H]
  \centering
  \includegraphics[width=1.0\textwidth]{img/image7.png}
  \caption{Resultado del analisis a profundidad del puerto 80 sobre la IP destino}
\end{figure}

La version que nos arroja es la de Apache httpdd 2.4.10 de debian, 
lo cual nos indica que el servidor web esta corriendo con esta version.

\subsection{Actividad 1: (Utilizar bandera -A)}

\textbf{Utilice la bandera “-A” para escanear el servicio web publicado en el puerto 80,
¿Cuál es el valor del campo “http-title” identificado por nmap?}

Para esto se realizo el siguiente comando:

\begin{lstlisting}[style=consolaSeguridad]
  sudo nmap -A -p 80 192.168.177.129
\end{lstlisting}

Lo que hace la bandera -A es que hace un escaneo pero mas agresivo, 
por lo que nos arroja mas informacion, la forma 
en que hace el esceneo es que hace un escaneo de version, un escaneo de sistema operativo, un escaneo de script y un escaneo traceroute, ahora bien 
la bandera -p es para indicar el puerto de interes, que vuelve a hacer en este caso 
el puerto 80, por lo que nos arroja la siguiente salida:

\begin{figure}[H]
  \centering
  \includegraphics[width=1.0\textwidth]{img/image8.png}
  \caption{Resultado del escaneo agresivo sobre el puerto 80}
\end{figure}

En nuestra salida el valor de http-title es :
\textbf{Apache2 Debian Default Page: It works}

En nuestra salida el valor de http-server -header es: 
\textbf{Apache/2.4.10 (Debian)}

Esto lo que nos quiere decir es que 
el servidor web esta corriendo con la version 
de apache 2.4.10 de debian, y que la pagina web 
que esta corriendo es la pagina por default de apache.

\subsection{Actividad 8: Ataque de diccionario con Hydra}

\textbf{¿Cuál es la cuenta vulnerable a un ataque de diccionario en el servidor web, cuál es su contraseña? Utilice el formato cuenta::password}

Ahora bien, para esto 
el comando que se nos pide 
es el siguiente:

\begin{lstlisting}[style=consolaSeguridad]
  hydra -l <USER> -P 10-million-password-list-top.txt -s PORT ssh://IP
\end{lstlisting}

Donde lo que hace este comando directamtne es atacar 
por medio del servicio SSH, ahora bien 
en la variable PORT, se tiene que colocar el puerto que se obtuvo por medio de los comandos anteriores de nmap,
que en este caso es el puerto 13337. 

En el caso de la varaible USER, se tiene que colocar el usuario 
que se obtuvo por medio de los comandos anteriores, 
en este caso es webadmin. 

Quedando el comando final de la siguiente manera:

\begin{lstlisting}[style=consolaSeguridad]
  hydra -l webadmin -P 100k-most-used-passwords-NCSC.txt -t 4 -s 13337 ssh://192.168.177.129
\end{lstlisting}

Donde en este caso, la bandera -l indica el usuario objetivo que es webadmin, 
-P le pasa nuestro diccionario descargado, -t 4 
limita los hilos de conexión a 4 para no saturar y bloquear el servicio SSH.

\textbf{Salida de la consola:}

\begin{figure}[H]
  \centering
  \includegraphics[width=1.0\textwidth]{img/image13.png}
  \caption{Ejecución exitosa del ataque de diccionario con hydra}
\end{figure}
En este caso, se tuvo que intentar varias veces, por que ssh me bloqueo varias veces, ademas de que se tardo aproximadamente 1 hora en encontrar la contraseña.


Este comando funciona de la siguiente manera, primero hace un intento de conexión con el usuario webadmin y la primera contraseña del diccionario, 
si no es correcta, hace un segundo intento con 
la segunda contraseña del diccionario, 
y así sucesivamente hasta que encuentra la contraseña 
correcta o se queda sin contraseñas en el diccionario.
